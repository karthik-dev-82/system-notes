Live /proc Explorer
=========================

:doc:`proc_filesystem` establishes the core idea: ``/proc`` files
aren't stored anywhere, they're generated by the kernel the instant
you read them. That's easy to state and a little abstract to
actually *feel* -- this page is a small simulated system where you can
click any path and watch it get generated fresh, right now, with
processes that spawn and exit on their own the whole time.

Play With It
------------------

A handful of named processes spawn and exit on a timer, same as a
real system's background churn. Click one to see its
``/proc/PID/status``, ``cmdline``, or ``fd/`` -- or click a
system-wide path (``cpuinfo``, ``meminfo``, ``uptime``, ``loadavg``)
on the left. Every click shows a brief "reading..." beat before the
result appears, and the numbers are computed fresh from this page's
own live state each time -- not cached, not replayed.

Two Things Worth Deliberately Testing
------------------------------------------------

* **Click the same file twice, a few seconds apart.** Try
  ``/proc/meminfo`` or ``/proc/loadavg`` right after a process spawns
  or exits, then again a bit later. The numbers actually move, because
  they're recomputed from whatever's alive *at the moment you ask* --
  exactly what makes ``/proc`` different from an ordinary file.
* **Select a process, then hit "kill" on a different one while you're
  reading the first one's status.** Nothing about your view breaks or
  goes stale -- but if you kill the *one you're currently looking at*,
  the display honestly tells you it's gone rather than continuing to
  show data for a process that no longer exists. That's the same
  reason a real ``/proc/PID`` directory doesn't linger after the
  process does: there was never a file there to begin with, only a
  live view of a process, and once the process is gone there's nothing
  left to view.

See :doc:`proc_filesystem` for the full reference -- every path this
widget simulates, the meaning of each process state letter, the
``/proc/sys`` tuning knobs (not simulated here, since those actually
change kernel behavior), and the ``/proc`` vs ``/sys`` comparison.
