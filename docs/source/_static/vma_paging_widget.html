Worth knowing, beyond what's animated here
  • Every page here is lazy, including code. This demo starts the text segment unmapped too -- real ELF text pages are demand-paged from the executable file on first access, exactly like heap and stack pages are demand-paged from nowhere (anonymous memory, zero-filled on first touch).
  • Frame exhaustion is simplified here on purpose. A real kernel facing "no free frames" doesn't just fail -- it runs page reclaim first: evicting a clean file-backed page (cheap, just discard it, re-read later) or swapping out a dirty anonymous page (expensive, must write it to disk first) to free one up, then retries the allocation. This demo has a fixed pool and reports out-of-frames directly so the scarcity itself stays visible.
  • The permission check always runs, present or not. Notice that writing to the read-only text segment faults whether or not that page has ever been touched before -- the R/W flag in the PTE is checked on every single access, not just the first one. This is also the exact mechanism behind copy-on-write after fork(): pages get marked read-only on purpose so the very first write anywhere triggers a fault, which is the kernel's cue to actually duplicate that page.
  • This widget shows the mechanism behind the picture drawn in A Process's Address Space: Play With It -- that page's segments are exactly the VMAs this page is allocating real memory for.
  • See Copy-on-Write After fork(): Play With It for exactly what that permission check enables: forking a process for free, then watching the very first write to a shared page trigger the real copy.
