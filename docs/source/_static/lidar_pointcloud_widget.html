Worth knowing, beyond what's interactive here
  • Every dot in the point cloud is a real ray-vs-wall intersection, not a placed decoration -- the same ray-segment intersection math used here is the same category of geometry a real LIDAR's processing pipeline runs, just against real 3D surfaces instead of 2D wall segments.
  • The nanosecond timings are real, not simplified for effect -- light travels at roughly 0.3 meters per nanosecond, so a wall 10 meters away really does produce a round-trip echo in the tens-of-nanoseconds range. That's exactly why LIDAR timing electronics have to be so precise: there's no room for slack at that timescale.
  • Terrestrial vs. Mobile is a real distinction in how the point cloud is built, not just a labeling difference. A stationary tripod scan only ever sees the room from one vantage point -- anything behind an obstacle from that one position stays a permanent gap. Moving the scanner (Mobile mode) fills in those gaps from new angles, which is exactly why mobile LIDAR is what vehicles and robots use to build a usable map instead of just one static snapshot.
  • This widget places the scanner at a position you already know -- you just clicked it there. Real mobile LIDAR almost never has that luxury: the platform's own position is itself uncertain and has to be estimated at the same time the map is being built. That bootstrapping problem is exactly what the companion SLAM widget covers next.
