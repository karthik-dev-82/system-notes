Worth knowing, beyond what's animated here
  • Every number in this widget really is recomputed at the moment you click, from this page's own simulated system state -- click the same file twice a few seconds apart (especially /proc/uptime or /proc/meminfo while processes are spawning and exiting) and you'll get different numbers both times. That's the entire point: real /proc files work the same way, generated by the kernel at read time, never sitting on disk in between.
  • The one thing this demo can't show you is the file's reported size actually being 0 in a real terminal's ls -l -- rendering that authentically needs a monospace directory listing, which is exactly what the ls -l line above each result reproduces. Try it for real: ls -lh /proc/cpuinfo on any Linux box will show a real byte count of 0 right next to a modification time, for a file that then prints a full page of text when you cat it.
  • /proc/loadavg's "total processes" count here is scaled up to look like a real system's (typically hundreds, between kernel threads and ordinary processes) -- this demo only names a handful for clarity, but the running-count portion is always accurate to what's actually alive in the simulation at that moment.
  • Killing a process here removes its /proc/PID entry instantly, for the same reason a real one disappears the moment a process exits: there's no file to keep around, because it was never stored anywhere in the first place -- it was a live view into a process that no longer exists.
