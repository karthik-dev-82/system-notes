What's happening right now
Set each task's delay, then click Run. Watch the console: all three "starting" lines print immediately, back to back -- await hasn't suspended anything yet at that point. Only once every task hits its await asyncio.sleep(...) does the event loop actually have to wait for anything.
Worth knowing, beyond what's animated here
  • Coroutines use await, not yield. If you've seen Python asyncio tutorials using yield inside a coroutine, that's the old generator-based coroutine style (@asyncio.coroutine + yield from), removed in Python 3.11. yield in modern async def code means something different entirely: it turns the function into an async generator, consumed with async for, not await -- a related but separate tool from what gather() works with. Every coroutine passed to gather() should use await, never yield.
  • The order-preservation guarantee is the whole point of this widget. asyncio.gather() always returns results in the order its arguments were given, never in the order the tasks actually finished. Set B's delay to 1 and A's to 5 and watch it happen: B finishes first by a wide margin, but its result still lands in the second slot of the returned list, because that's where fetch_data("B", ...) was positioned in the original call.
  • asyncio.TaskGroup (Python 3.11+) is the newer recommended alternative for exactly this pattern, with better error handling: if one task raises, gather() by default lets the others keep running silently in the background, while TaskGroup cancels its siblings immediately and reports the failure clearly. Same ordering guarantee, safer failure behavior: 
    async def main():
    async with asyncio.TaskGroup() as tg:
        a = tg.create_task(fetch_data("A", 2))
        b = tg.create_task(fetch_data("B", 1))
        c = tg.create_task(fetch_data("C", 3))
    results = [a.result(), b.result(), c.result()]
