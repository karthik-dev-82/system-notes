Worth knowing, beyond what's animated here
  • A directory is itself basically just a file whose content is a list of (name, inode number) pairs. That's what a "directory entry" is -- so ls is really reading a small file and printing the names it finds, and rm is really just deleting one of those pairs.
  • Hard links can't cross filesystems (a hard link is genuinely a second name for the same inode number, and inode numbers are only unique within one filesystem) and can't point at directories on most systems (to keep the directory tree from becoming a graph with cycles). Symlinks have neither restriction, since a symlink is just a file containing a path string -- it doesn't know or care what filesystem that path resolves through.
  • The VFS (virtual filesystem switch) is the reason open(), read(), write(), and close() work identically whether the file is on a spinning disk, in RAM (tmpfs), doesn't physically exist at all (procfs, see the live /proc explorer), or is on another machine entirely (NFS). Every filesystem type implements the same handful of operations the VFS expects, and userspace code never has to know which one it's actually talking to.
  • Mounting something over a non-empty directory doesn't delete what was there -- it just becomes unreachable until you unmount. This demo's /mnt example (try it in the Mounting tab) is exactly that: the file that was already at that path reappears the instant you unmount, completely unchanged.
