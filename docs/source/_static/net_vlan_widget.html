Worth knowing, beyond what's animated here
  • The extra field in a tagged frame is real and standardized: 802.1Q inserts a 4-byte tag right after the source MAC address -- a 2-byte TPID (Tag Protocol Identifier, always 0x8100 for 802.1Q) followed by a 2-byte TCI (Tag Control Information) that packs in a 3-bit priority, a 1-bit drop-eligible flag, and the 12-bit VLAN ID itself (which is why VLAN IDs top out at 4094, not some rounder number).
  • The physical NIC (eth0) never actually "contains" three separate networks -- it's one wire carrying frames that all happen to have a tag field. The sub-interfaces (eth0.10, eth0.20, eth0.30) are what do the actual demultiplexing: each one only accepts frames tagged with its own VLAN ID and strips the tag before handing the frame up the stack, so from an application's point of view each VLAN just looks like its own ordinary network interface.
  • Isolation here is a property of the tag, not of physical distance -- a guest device one inch from a security camera, both plugged into the same switch, still can't see the camera's traffic if they're on different VLANs and nothing is explicitly configured to route between them. That's the entire security value: segmentation without separate cabling.
  • Getting from "isolated" to "these VLANs can talk when we want them to" requires a device operating above Layer 2 -- a router, or an L3 switch -- explicitly configured to forward between the VLANs (often called "router-on-a-stick" when it's done over a single trunk link). Nothing in this demo does that on purpose: real isolation is the default, and crossing it is a deliberate configuration step.
