Worth knowing, beyond what's animated here
  • This widget's numbers are real math, just tiny. p=23, g=5 for Diffie–Hellman and n=33, e=3, d=7 for the signature are small enough to brute-force by hand in seconds — that's exactly why real SSH uses primes hundreds of digits long (or elliptic-curve variants like Curve25519) instead. The *algorithm* shown here is the genuine one; only the key size is shrunk down to fit on screen.
  • The order matters: key exchange (and the encrypted tunnel it produces) always finishes before authentication starts. That's true for both password and public-key auth -- your credentials are never the first secret to cross the wire, the shared session key is.
  • Host key checking is the part people click through without reading, but it's the only defense against a machine-in-the-middle silently relaying (and reading) your entire session. A changed fingerprint on a host you've connected to before is a real warning sign -- run ssh-keygen -R hostname only after confirming with the server's actual admin that the key legitimately changed (a reinstall, a new host key rotation), not just to make the warning go away.
  • Public-key auth proves possession, not knowledge. A password is a piece of knowledge that has to be transmitted (even if encrypted) to be checked. A signature proves you hold the private key without the private key -- or anything equivalent to it -- ever leaving your machine, which is why it can't be phished, leaked from a server-side breach, or reused if that one server is compromised.
