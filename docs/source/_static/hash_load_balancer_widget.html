Worth knowing, beyond what's animated here
  • What's a "flow"? A flow is the standard 5-tuple that uniquely identifies one connection: (source IP, destination IP, source port, destination port, protocol). Two packets belong to the same flow if and only if all five values match. This matters here because every NEW connection -- even from the exact same client, to the exact same server -- gets a fresh, essentially random source port from the OS, which makes it a genuinely different flow with a genuinely different hash.
  • This is why clicking the same client twice can send its two requests to two different servers: flow-hash load balancing gives you connection-level stickiness (this one TCP connection stays on one server for its whole lifetime), not user-level stickiness (the same human, across multiple separate connections, staying on one server). The "Resend Last Flow" button demonstrates the connection-level guarantee directly -- same 5-tuple in, same server out, every time.
  • Real HTTP-aware load balancers that need actual user/session stickiness typically hash (or read) something at the application layer instead -- a session cookie, a client-supplied user ID -- specifically because it doesn't change every time the OS picks a new ephemeral port. See the conceptual Hash Load Balancer guide for that use case.
  • The hash function used in this demo is a small illustrative one, chosen only for reproducibility. Real load balancers and routers commonly use CRC32, a Toeplitz hash (used by NIC hardware for RSS -- receive-side scaling), or similar -- the specific algorithm matters far less than the property this whole demo is about: same input, same output, every time.
  • The "naive" in naive modulo hashing isn't about the hash function -- it's about % number_of_servers specifically. Add or remove a server and the modulus changes, which silently reroutes a large fraction of all existing flows even though nothing about those flows changed. See the consistent hashing page for the fix -- it's the very next page after this one for a reason.
