Worth knowing, beyond what's interactive here
  • Both panels see the exact same real scan and the exact same noisy motion command at every step -- the only difference is what each one does with that noisy command. The left panel just integrates it directly (classic dead reckoning). The right panel uses it only as a starting guess, then runs real ICP (Iterative Closest Point): match the new scan's points against the nearest points already in the map, fit the rigid rotation+translation that best aligns them, repeat a few times.
  • Scan matching does not win every single run. Empirically, across many runs of this exact path, it ends closer to the true position in roughly 85% of them -- not 100%. Occasionally a lucky noise draw lets raw odometry end up closer by chance, or an unlucky scan gives ICP a poor match. Click "Run 100 trials & compare" to see the real, live aggregate rather than taking that number on faith.
  • Point-to-point ICP has a small built-in residual error, even from a perfect starting guess. Two scans taken from slightly different positions sample the same walls at different points along them -- so even flawless correction can't align two scans to exactly zero error. This is a genuine, well-known property of point-to-point ICP (as opposed to point-to-plane methods, which reduce but don't eliminate this either) -- not a bug being hidden here.
  • The real payoff isn't any single step, it's that the gap widens as the path gets longer. Dead-reckoning error compounds step after step with no ceiling. Scan-matching error gets re-anchored near the map every single step, so it does not compound the same way -- watch the error chart's two lines diverge further apart the more steps you take.
  • This widget stops at scan-to-map matching. It deliberately does not cover loop closure -- recognizing you've returned to a previously-mapped place and using that to retroactively correct the entire trajectory -- which is the other major technique real SLAM systems use and a natural next widget if this territory gets revisited.
