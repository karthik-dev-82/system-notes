Worth knowing, beyond what's interactive here
  • The cart's checkout code never mentions any specific discount. It just calls strategy.calc(cart) -- whatever object is plugged in decides the math. That's the entire pattern: an interface (one method, same signature, different behavior per implementation) plus a context that only ever talks to the interface.
  • "Buy 2, get 1 free" isn't automatically the best deal -- it depends on the cart. With three items at quantities 3, 1, and 5, it beats a flat 10% off here because two of the three lines have enough quantity to earn a free unit. Change the quantities and watch which strategy wins change with it.
  • The branch-based version isn't a strawman. A single function with an if/else per case is a completely normal way this gets written before anyone reaches for Strategy -- it works fine right up until a new case needs adding, at which point it means re-opening and re-editing a function whose other branches are already shipped, tested, and (ideally) left alone.
