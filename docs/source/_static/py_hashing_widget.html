Worth knowing, beyond what's animated here
  • Every number in this widget (PyDict_MINSIZE=8, PySet_MINSIZE=8, the perturb-based probe recurrence, the 2/3 vs 3/5 load-factor thresholds, the growth formulas) was read directly from CPython's own source (Objects/dictobject.c, Objects/setobject.c) rather than recalled from general knowledge -- the two implementations really do differ this specifically, it's not a simplification for teaching purposes.
  • The hash values shown here are from a small illustrative hash function, not real CPython hash() output -- real string hashing in CPython is randomized per-process (SipHash, seeded by PYTHONHASHSEED) specifically so that hash-flooding attacks against dict-backed structures (like a web server's request-parameter dict) can't be engineered by an attacker who knows the algorithm.
  • dict resizes before the insert that would exceed capacity (a pre-emptive check: CPython keeps a running "usable slots left" counter and resizes the moment it would hit zero); set resizes after the insert that crosses the threshold (it inserts first, then checks fill*5 >= mask*3). Both are correct and both keep the table below its load factor at all times -- they just checked at different points in the CPython codebase's history and were never unified.
  • set's collision resolution isn't identical to dict's: at each landing index, set first checks up to 9 consecutive slots (LINEAR_PROBES) before doing the pseudo-random perturb jump that dict uses on every single step. In a small table those 9 slots usually don't fit without wrapping, so the difference mostly shows up once a set has grown past its initial size -- it's a real optimization for cache locality on larger tables, added to set and never ported to dict.
  • The most practically important fact here isn't the internals -- it's this: never rely on set iteration order. ``dict`` has preserved insertion order as a language guarantee since Python 3.7; ``set`` has never made that promise and its actual order (as this widget shows) depends on hash values and table layout, which can change between Python versions, between runs (hash randomization), and after any resize.
