What this simplifies, for the technically curious
  • This models classic TCP Reno / NewReno -- additive-increase/multiplicative-decrease (AIMD) congestion control, exactly as described in RFC 5681. It's the textbook model, and it's still a correct description of one real algorithm -- but it isn't the only one in use today.
  • Linux's actual default since kernel 2.6.19 is CUBIC, not Reno. CUBIC grows the window along a cubic function of time since the last loss rather than a strict AIMD line/doubling, and it's deliberately less aggressive about backing off, which matters a lot on high-bandwidth long-distance links. Google's BBR goes further and doesn't treat packet loss as the primary congestion signal at all -- it continuously estimates the bottleneck bandwidth and round-trip time and paces sends against that model instead.
  • The "found the limit" moment has a real name: ssthresh (slow start threshold). Slow start doubles cwnd every RTT until cwnd would reach or exceed ssthresh, at which point congestion avoidance's +1-per-RTT growth takes over.
  • Real slow start doesn't start at cwnd = 1 segment anymore either. RFC 6928 raised the typical initial window to around 10 segments on modern stacks, specifically to make short connections (most web requests) finish faster.
  • Whether a loss becomes a fast retransmit (halve and keep going) or a timeout (collapse to 1 and restart slow start) isn't random here -- it's driven by whether there were enough packets already in flight to generate 3 duplicate ACKs (this sim uses cwnd ≥ 4 as that cutoff). That's the real reason timeouts hit small windows hardest: there simply aren't enough packets in flight yet to trigger the faster recovery path.
  • Real TCP typically uses SACK (Selective Acknowledgment) rather than plain cumulative duplicate ACKs, so the sender learns exactly which segments are missing instead of just "still waiting for the oldest unacked one."
  • cwnd is congestion control. There's a separate, unrelated mechanism called flow control using the receiver's advertised window (rwnd) to stop a fast sender from overrunning a slow receiver's buffer. The actual amount in flight at any moment is min(cwnd, rwnd) -- this widget only visualizes the cwnd half.
