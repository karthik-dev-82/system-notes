Worth knowing, beyond what's interactive here
  • GUI terminals and SSH sessions share the exact same /dev/pts/N allocator. There's nothing structurally different between opening a terminal emulator locally and SSHing in remotely -- both ask the kernel for the next pseudo-terminal, and both get the lowest currently-free index. That's the same "one shared pool, lowest free index" rule the USB device binding widget shows for /dev/ttyUSB* -- not a coincidence, it's a general allocation pattern the kernel reuses across subsystems.
  • Freed pts indices are reused, but never retroactively -- close pts/0 while pts/1 is still open, and pts/1 keeps its number. The next new session gets 0 back. Try it above: open three sessions, close the first, then open a fourth and watch it reuse the freed slot while the still-open second session is untouched.
  • Switching virtual consoles never logs anyone out. A login session on tty3 keeps running whether or not tty3 is the one currently displayed -- "active" (what's on screen) and "logged in" (whether a session exists there) are independent bits of state.
  • The GUI session's console (modeled here as tty1) can't be logged out from this widget -- historically the desktop often lived on tty7, but modern systemd/Wayland setups commonly put it on tty1 or tty2; the exact number varies by distro, the "it's just another VC, permanently occupied" mechanism doesn't.
  • /dev/ttyS0 is a real physical wire -- only one login session can ever occupy it at a time, unlike the PTY pool which can grow to as many concurrent sessions as you open.
