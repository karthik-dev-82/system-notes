Beyond the Bridges

Where memory and I/O actually connect in a modern chip — and why "northbridge" and "southbridge," the terms most explainers still use, describe almost nothing built in the last decade.

Short answer to "are these terms still valid": mostly no. Northbridge/southbridge described a real, physical two-chip layout that was standard on Intel motherboards through roughly 2008. Intel folded the northbridge's job (memory controller, PCIe) into the CPU package starting with Nehalem, and renamed the southbridge's descendant the Platform Controller Hub (PCH). AMD did the same with its own chiplet layout. The words chipset and PCH are still current; northbridge and southbridge are historical, and neither term was ever really used to describe ARM chips, which took a different physical route to the same problem from the start.

The rest of this page walks through the old model briefly for grounding, then the two current answers — x86 (Intel/AMD) and ARM — side by side, with a floor plan for each.

§1

The one thing that never changed

Before getting into what moved where, it's worth naming the one idea that's been true since long before 2008 and is still true today: a CPU core only has three ways to talk to the outside world — a physical memory address space, a (mostly vestigial, on x86) separate I/O address space, and interrupt lines. Everything else — RAM, a graphics card, an NVMe drive, a USB controller — is reached by putting a request on one of those, and something downstream decides what actually answers it.

What's changed repeatedly is where the "something downstream" physically lives — which chip, on which side of which package boundary, decides that a given address means "RAM" versus "the drive controller." That's the part this page is actually about.

§3

Modern x86 Intel & AMD, current

The northbridge's job didn't disappear — it moved inside the CPU package. Every current Intel and AMD desktop or laptop chip has its memory controller and PCIe root complex on the same package as the cores, not on a separate chip reached over a shared bus. What's left of the southbridge is a single companion chip, reached over a narrow, dedicated, point-to-point link instead of a shared bus.

Intel: SoC tile + PCH

Since Meteor Lake and continuing through Arrow Lake and Panther Lake, Intel builds its client CPUs from separate tiles on one package: a compute tile (cores), a graphics tile, an SoC tile, and an I/O tile. The SoC tile carries the DDR5 memory controller and the PCIe root complex — the northbridge's exact job, just built as one tile among several rather than a standalone chip. The PCH is still a physically separate chip on the motherboard, reached over DMI (itself a PCIe-based point-to-point link, not a shared bus), and current desktop platforms still carry a chipset model name in the old tradition — Z890 for the current Arrow Lake-S desktop generation.

AMD: CCD + IOD

AMD's Ryzen chips are built from chiplets: one or more Core Complex Dies (CCDs), which hold only cores and cache, plus a separate I/O Die (IOD) that holds the memory controller and PCIe root complex — again, the northbridge's job, on its own die but still inside the CPU package. Each CCD talks to the IOD over Infinity Fabric. The motherboard chipset (X870, B850, and similar current AM5 chipsets) plays the same role Intel's PCH does, connected over PCIe rather than DMI, and AMD's own materials still call it "the chipset" — not southbridge, but not entirely divorced from the concept either.

The practical upshot for anyone reasoning about performance: a GPU or your primary NVMe drive is one hop from the CPU cores in a way a USB device or a SATA drive isn't. That asymmetry is exactly the northbridge/southbridge split, preserved — it's just that one side of the split now lives inside the CPU's own package instead of on a second chip.

§4

ARM no bridges, ever

Northbridge/southbridge was never really an ARM concept, for a structural reason: ARM Holdings doesn't build chips, it licenses an instruction set and, optionally, core and interconnect designs, to companies (Apple, Qualcomm, Samsung, Amazon, Ampere, and dozens more) who each build their own complete chip. There was never a standard "ARM motherboard" for a chipset industry to grow up around the way there was for Intel-compatible PCs. Instead, essentially everything ships as one system-on-chip (SoC) — and what's actually on that chip varies enormously by who built it and what it's for.

The two ends of that range look different enough to be worth drawing separately.

Mobile & laptop: unified memory, one die, no chipset

Apple's M-series is the clearest public example: CPU cores, GPU cores, and the Neural Engine all sit on one die and share one pool of LPDDR memory over a single wide, high-bandwidth path — Apple's own unified memory architecture. There's no discrete GPU with its own VRAM to copy data into, and no separate chipset chip on the logic board handling storage or USB — those controllers are on the SoC die too. Qualcomm's Snapdragon and other mobile ARM SoCs follow the same basic shape: one die, on-chip fabric, memory attached directly to the package.

Server: a coherent mesh, not a bus

ARM's Neoverse platform — the basis for AWS Graviton, Ampere's Altra/AmpereOne, and others — scales to dozens or low hundreds of cores, which a single shared bus can't do without becoming the bottleneck. Instead, ARM's CMN (Coherent Mesh Network) interconnect arranges cores, cache, memory controllers, and I/O as nodes on a 2D mesh, using the AMBA CHI protocol to keep every core's view of memory consistent. Memory controllers and the PCIe root complex sit at the mesh's edges, functionally in the same place the northbridge used to be — just reached by mesh routing instead of a shared bus, and built by the chip vendor into the same die as the cores rather than existing as a separate part at all.

There's no ARM equivalent of "PCH" or "chipset" to look up, because the concept doesn't map cleanly — not because ARM chips are simpler. A high-end Neoverse server SoC is arguably more complex to route than a modern x86 CPU package; it just never had a second physical chip to hand the job to.
