Worth knowing, beyond what's animated here
  • Both schemes look balanced at first. Click "Insert Next 25 Keys" four times and both sides look roughly even -- the range shards were sized to exactly fit that first batch. Keep clicking past that point and only the range-based side keeps dumping everything on the last shard, because a real auto-increment primary key never stops growing, and the last shard's range was always open-ended. This is the real, documented "hot shard" anti-pattern for range sharding on monotonically increasing keys -- not a contrived edge case.
  • "Add a Shard" is two structurally different operations. For hash-based (naive modulo, no virtual nodes), adding a shard recomputes hash(key) % N for every single key and typically reshuffles the large majority of them -- the exact same (N-1)/N-shaped cost demonstrated with real numbers on :doc:`hash_load_balancer_interactive` and :doc:`consistent_hashing_interactive`. For range-based, adding a shard means splitting one range in two -- only the keys in the split shard move; every other shard is completely untouched, because splitting a range is a local operation with no need to touch keys outside it.
  • Range queries are the other half of this trade. Run a query for keys 10-20 -- range-based touches exactly the one shard whose range covers that window. Hash-based has to ask every single shard, because keys 10 through 20 could have hashed anywhere -- this is real scatter-gather, not a pessimistic assumption, and it's the structural reason range sharding stays attractive for time-series and other range-scanned data despite its hot-shard risk.
  • Real systems mitigate the hot-shard problem several ways: adding a random or hashed prefix to an otherwise-sequential key (trading away some range-query locality on purpose), pre-splitting ranges ahead of expected growth, or -- as this widget's "Add a Shard" button demonstrates -- automatically splitting a shard once it crosses a size threshold, which is exactly what systems like HBase, Bigtable, and DynamoDB do under the name "auto-splitting."
