Worth knowing, beyond what's animated here
  • No false negatives is a structural guarantee, not a probability. Once a word's k bits are set, they can only ever be set -- nothing in this data structure ever clears a bit. So a word you added will test positive forever, no matter how many other words get added after it. False positives, in contrast, are a real possibility any time enough other insertions happen to set all of some other word's k bits by coincidence.
  • Drag m down or k up (past the useful point) after adding a few dozen words and watch the measured false-positive rate climb -- a smaller array or worse hash-count choice runs out of "room" to stay selective. There's a real optimal k for a given m/n ratio (k = (m/n) ln 2); too few wastes the array's capacity to discriminate, too many sets bits faster than it gains anything.
  • The two hash functions here (FNV-1a and djb2) are real, standard string hashes -- the same FNV-1a used on this site's consistent hashing page. The k "independent" hash functions are actually derived from just these two, combined as h_i(x) = h1(x) + i * h2(x) -- a real, standard technique called Kirsch-Mitzenmacher double hashing, not a shortcut specific to this demo. It's provably about as good as k genuinely independent hash functions for this purpose.
  • Real systems use exactly this structure to avoid expensive lookups: Chrome's Safe Browsing used one to avoid a network round-trip for every URL that's obviously not malicious; Cassandra and HBase use one per SSTable to skip disk reads for a key that's obviously not there; Bitcoin light clients used one to filter which blocks are worth downloading in full.
