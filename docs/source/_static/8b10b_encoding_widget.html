Worth knowing, beyond what's animated here
  • This is a from-scratch construction, not a transcription of the real IBM/ANSI 8b/10b table. Reproducing that historical lookup table from memory risked shipping a subtly wrong copy of a real industry standard, so this widget builds its own 5-bit+3-bit table instead -- same real mechanism (sub-block split, running disparity, dual-codeword correction), verified exhaustively for the same properties, just not byte-for-byte identical to the patented original.
  • Every symbol here is proven to have run length ≤5 across its own 6-bit/4-bit join, checked for all 256 bytes and both starting disparities -- not sampled, every single one. The boundary between two consecutive symbols is proven to stay ≤6 (checked exhaustively across every reachable symbol pair), with the stricter textbook ≤5 holding in the large majority of cases. The real industry table, engineered far more carefully than this widget's from-scratch one, achieves a strict ≤5 everywhere -- that extra rigor is the gap between a teaching construction and the real standard.
  • Running disparity correction is real and self-steering, but this widget doesn't claim a hard mathematical bound on how far it can drift over an arbitrarily long stream -- only that it stays small (single digits) at the scale an interactive demo actually reaches. Watch the RD number in the breakdown panel pull back toward zero after every "plus"/"minus" choice.
  • Send 00 then look at the stream: the encoder never once sends a flat run of 10 zero bits, which is the entire reason this scheme exists -- a receiver with no clock wire needs those transitions to stay synced.
