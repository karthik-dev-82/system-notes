Worth knowing, beyond what's animated here
  • The partition routing is a real hash function (djb2 over the key string, taken mod the partition count), not a random assignment dressed up to look deterministic -- that's exactly why the same sensor ID lands in the same partition every single time, in this widget and in real Kafka.
  • A rebalance never resets progress. Click "+ Add consumer" on a group that already has messages polled, and watch the log confirm every partition's offset stayed exactly where it was -- ownership of a partition can move between consumer instances, but the read position belongs to the *group*, not to whichever consumer happens to be polling it at the moment.
  • More consumers than partitions just means idle consumers. A group can never usefully have more active consumers than the topic has partitions -- try adding a third consumer to a group and watch it sit with nothing assigned.
  • "Replay" is the one thing that makes Kafka different from most message queues: resetting a group's offsets re-delivers everything from the start, because the messages were never deleted on read in the first place -- only the group's bookmark moved.
