unique_ptr: Play With It

Exclusive ownership, enforced by the compiler: exactly one unique_ptr owns a given block at a time, and its destructor deletes that block automatically -- on every exit path, not just the ones you remembered to handle.
void process_raw(bool fail_early) {
int* p = new int(42);
if (fail_early) {
return; // p never freed on this path
}
delete p;
}
void process_unique(bool fail_early) {
auto p = std::make_unique<int>(42);
if (fail_early) {
return; // p's destructor STILL runs here
}
// no delete needed -- destructor runs when p goes out of scope
}

Worth knowing, beyond what's animated here
  • The mechanism behind "automatic cleanup" is nothing exotic -- it's the same stack-unwinding/destructor machinery every local object gets. unique_ptr just wraps a raw pointer and does exactly one useful thing in its own destructor: delete whatever it currently owns (or nothing, if it's empty). It isn't magic, it's a very small class using a mechanism that's always been there.
  • The "Copy p1 -> p3" button is disabled because that line genuinely does not compile in real C++ -- unique_ptr's copy constructor is explicitly deleted (unique_ptr(const unique_ptr&) = delete;). This isn't a runtime check; the compiler refuses to build code that tries it, which is exactly the point: "two owners of one block" becomes structurally impossible to write instead of a bug you have to remember to avoid.
  • std::move doesn't move anything by itself -- it's just a cast that tells the compiler "treat this as movable." The actual transfer happens in unique_ptr's move constructor, which copies the raw pointer into the new object and sets the old object's pointer to nullptr. That's genuinely all a move is here: one pointer copy plus one pointer reset, versus a raw pointer's copy which would leave two variables pointing at the same block with no ownership rule at all.
  • This tab is the direct fix for both bugs on the previous page: the heap-leak tab's "forgot to call delete on one exit path" and the use-after-free tab's "two raw pointers, no ownership rule" are exactly the two failure modes unique_ptr makes structurally unreachable -- one by construction (RAII), the other by the compiler (deleted copy constructor).
