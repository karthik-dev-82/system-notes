Worth knowing, beyond what's animated here
  • This is the classic 32-bit layout, deliberately -- it's the clearest way to see the shape, and it's exactly the diagram most operating-systems courses still teach. 64-bit Linux uses the same structure (kernel space, stack, mmap region, heap, BSS, data, text) over a vastly larger address space, so the picture doesn't change, only the amount of empty space between the pieces does.
  • The randomized offsets here are illustrative, not exact kernel constants. Real ASLR entropy depends on architecture and kernel version. The important idea -- that the stack, shared-library, and heap base addresses move on every run, while their relative order to each other never does -- is exactly right.
  • Modern distros also randomize the executable's own base address via position-independent executables (PIE) -- this widget keeps the text segment's start fixed for clarity, matching the classic (pre-PIE-by-default) picture this diagram comes from.
  • This diagram shows where each segment lives. It doesn't yet show what backs that space with actual RAM -- VMAs, Page Tables & the Lazy Kernel: Play With It picks up exactly where this leaves off.
